# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
## Проект: Gemini Mobile Gateway & Android WebView Client

### 1. НАЗНАЧЕНИЕ И ЦЕЛИ СИСТЕМЫ
* **Назначение:** Создание автономного клиент-серверного мобильного решения для прямого, высокоскоростного доступа к моделям Gemini 3.x (включая флагман gemini-3.8-flash) с мобильных устройств без необходимости VPN на стороне клиента.
* **Цели проекта:**
  1. Проксирование и обход региональных ограничений через зарубежный VPS.
  2. Отказоустойчивость: настойчивый дозвон до 100 попыток со случайным смещением (джиттером 2.5-4.5с) при кодах 503 и 429.
  3. Обход квот бесплатного тарифа: автоматическое отключение Google Search при отсутствии биллинга.
  4. Хронологическая точность: динамическое внедрение даты и времени по поясу UTC+4 (Ижевск).
  5. Мультимодальность: передача картинок и файлов через Base64 inlineData.
  6. Двойной клиент: работа в режиме PWA и нативного Android APK.

### 2. АРХИТЕКТУРА СИСТЕМЫ
Смартфон пользователя (HTTP / SSE напрямую без VPN)
  -> Сервер VPS (Nginx Reverse Proxy на порту 80, buffering=off)
  -> Node.js Express Gateway (PM2, порт 3000)
  -> Google Generative Language API (gemini-3.8-flash, gemini-3.5-flash-lite).

### 3. ТРЕБОВАНИЯ К КОМПОНЕНТАМ
* **Серверный шлюз:** Node.js 18+ LTS, Express, PM2. Потоковая передача SSE. Лимит тела запроса 50 МБ.
* **Веб-интерфейс и PWA:** Адаптивная мобильная верстка, safe-area, переключатель моделей, манифест manifest.json (standalone) и кэширующий sw.js.
* **Android клиент:** Полноэкранный WebView на Java 17, обработка системного файл-менеджера WebChromeClient.onShowFileChooser, перехват кнопки Назад.
* **CI/CD:** GitHub Actions (.github/workflows/build-apk.yml) для облачной сборки APK без нагрузки на сервер.

### 4. СПЕЦИФИКАЦИЯ API
* POST /api/chat — передача массива contents, model, systemInstruction. Возврат потока SSE (statusText, connected, text, [DONE]).
* GET /api/health — диагностика состояния и проверка текущего времени сервера.
